# The 2014 edition's GUI — what to match, and where it is written down

This is the reference for the port's menus/HUD. It is decoded from the **2014**
build, `swf_orig/runIII.swf`, because that is the edition the port is measured
against. Nothing here is inferred from the port.

---

## 0. Read the right tree

| tree | came from | what it is |
|---|---|---|
| `swf_orig/decomp/runIII/scripts/` | `swf_orig/runIII.swf` | **the 2014 edition** — the ground truth |
| `src/`, `readable_src/` | `Run3.swf_Decompiler.com.zip` at the repo root, which is byte-identical to `swf_orig/run3-adobeflash.swf` (and to `~/Downloads/Run3.swf`) | a **later** build |

`bake_src.py` states this in its header: `src/` is decompiled from
`Run3.swf_Decompiler.com.zip`. That zip is the *adobeflash* SWF, not `runIII`.
So `readable_src/` — the tree the cutscene / layout / level decodes were read
from — is the **later** build, and any GUI read from it has to be re-checked
against `runIII` before it is trusted.

The two menus are not the same screen, and the difference is not cosmetic:

| | 2014 (`runIII`) | later (`src/`) |
|---|---|---|
| menu class | `com/player03/run3/menu/§-__-_--__-_-§.as` | `com/player03/run3/menu/§;!G§.as` |
| placement | **absolute pixel writes** (`x = …`, `y = …`) | the `com.player03.layout` gravity/anchor engine |
| top-right | `menu/CreditsIcon.png` | `menu/GearIcon.png` |
| cutscene icon | does not exist | `menu/CutsceneIcon.png` |
| `menu/QualityIcon.png` | does not exist | present |

So the 2014 menu is *much* easier to reproduce than the later one: it needs no
layout engine, just the numbers below.

## 1. ScaledAssets — how the 2014 turns design units into pixels

`haxeutils/display/ScaledAssets.as` (both builds; the 2014's is identical in
substance):

```
scaleX, scaleY                     // the design scale, set once at boot
drawing a bitmap:  scaleX * 2      // Bitmap.scaleX = 2*scaleX, scaleY = 2*scaleY
getWidth( v)  ->  v * scaleX       // a horizontal distance
getHeight(v)  ->  v * scaleY       // a vertical distance
font size (v) ->  v * scaleY
assets are addressed as "img/" + name, e.g. "img/menu/Run3.png"
```

**Note the ×2.** A bitmap is drawn at *twice* the design scale, while a
distance is drawn at the design scale. That is why the menu constants look small
(90, 40, 30, 25, 20) next to a 642-pixel-wide title: the title covers `642*2*sx`
of screen while the margin is `90*sx`.

The design box the port already uses for the map is the same one:
`k = min(BASE_W/3000, BASE_H/2000)`, `sx = sy = k`. Gaps and the map's rule come
from the same `ScaledAssets` instance, so the menu must use the same `k`.

At the port's base box (`BASE_W 960`, `BASE_H 720`): `k = 0.32`, `2k = 0.64`.

## 2. The 2014 main menu, element by element

From `com/player03/run3/menu/§-__-_--__-_-§.as`, `create()` and `reset()`.
`sw`/`sh` are `stageWidth`/`stageHeight`. `sx`/`sy` are the ScaledAssets scales.

Created on entry, in this order:

| element | asset | position |
|---|---|---|
| title | `menu/Run3.png` (642×212) | `x = (sw − 642·2sx)/2`, `y = 90·sx` |
| links bar `§--___--_--§` | — | `x = 2·(20·sx)`, `y = 20·sx` |
| credits / options | `menu/CreditsIcon.png` (123×123) | `x = sw − w − 20·sx`, `y = 20·sx` |
| rotating links `§-__--_---_§` | — | `x = credits.x − w − 20·sx`, `y = 20·sx` |
| character select `§---_---_-_-§` | characters | `y = sh · 0.3` (x internal) |
| Play | `menu/PlayGame.png` (298×176) | `x = (sw − w)/2`, `y = playY + sh · 0.05` |
| "Explore mode" (text button, size 100) | — | `x = sw/2 − w − 40·sx`, `y = playY` |
| "Infinite mode" (text button, size 100) | — | `x = sw/2 + 40·sx`, `y = explore.y` |
| "Galaxy map" (+ `map/MapIcon.png`, 163×135) | — | `x = (sw − w)/2`, `y = infinite.y + infinite.h + 30·sx` |
| badge `§-_-_-_--_-_§(0xFFFFFF, 0xFF0000, 70)` | — | `x = galaxy.x + galaxy.w`, `y = galaxy.y` |
| "Shop" (+ `menu/Shop.png`, 64×64) | — | `x = (sw − w)/2`, `y = galaxy.y + galaxy.h + 30·sx` |
| badge (same class) | — | `x = shop.x + shop.w`, `y = shop.y` |
| leaderboards | `menu/Leaderboards.png` (100×100) | `x = 25·sx`, `y = sh − h − 25·sx` |
| achievements | `menu/Achievements.png` (100×100) | `x = lb.x + lb.w + 25·sx`, `y = lb.y` |
| edit | `menu/EditIcon.png` (131×133) | `x = ach.x + ach.w + 25·sx`, `y = ach.y + ach.h − h` |
| sprite `§---___-_-§` (the text layer) | — | added last, on top |

with

```
playY = charSelect.y + charSelect.<box>.height + 90·sx
```

The icons whose **lowercase-name check** the port already ships as
`assets/images/menu_*.png` are the same bytes: the 2014 doesn't have a
`QualityIcon`, a `CutsceneIcon` or a `GearIcon`, and the port's
`menu_qualityicon.png` is therefore from the later build (see §0).

Evaluated at 960×720 (`k = 0.32`, so `2k = 0.64`, margins `20·sx = 6.4`,
`25·sx = 8`):

| element | native | drawn | x | y |
|---|---|---|---|---|
| title | 642×212 | 411×136 | 274 | 29 |
| credits | 123×123 | 79×79 | 875 | 6 |
| leaderboards | 100×100 | 64×64 | 8 | 648 |
| achievements | 100×100 | 64×64 | 80 | 648 |
| edit | 131×133 | 84×85 | 152 | 627 |
| Play | 298×176 | 191×113 | 385 | `playY + 36` |
| char select | — | — | — | 216 |

(`playY` needs `charSelect.<box>.height`, which the character-select class
supplies; read it when implementing.)

## 3. What the port draws today

`render_menu()` in `render.c` is an invented screen — "Run 3 / Tunnel Runner
Tribute / Play / Infinite Mode / Character: <grid> / Click to select |
Fullscreen" — with a procedurally drawn character grid. It shares **no**
element, position, asset or font with §2. Replacing it is the main-menu half of
GUI parity.

Two things the replacement needs that the port does not have yet:

* the menu bitmaps, which are baked into the wasm as C arrays. The pattern is
  already in the tree: `levels/bake_map.py` emits `levels/map_assets.h`
  (`static const uint32_t name[]`, `#define NAME_W/_H`), which `render.c`
  includes. A `bake_menu.py` → `levels/menu_assets.h` alongside it is the
  smallest way in.
* the 2014's text face. The port's `draw_text` is its own font; the 2014 menu
  sets `TextFormat.font = Main.<font>` and sizes text at `v * sy`
  (90 and 100 design units for the two text-button sizes).
